## Princípios operacionais

- **Um chat do Project não é um processo que acompanha os outros chats em tempo real.** Ao iniciar trabalho, ler os documentos atuais e as Issues relevantes.
- Cada setor tem **escopo delimitado** e entrega versões rastreáveis. Nenhuma aprovação deve existir apenas numa conversa.
- Uma solicitação entre setores deve virar **GitHub Issue**, vinculada ao arquivo e ao setor de origem.
- **Rascunho não é especificação aprovada.** Codex não deve inventar decisões ausentes.
- O sistema deve começar enxuto, com custos controlados e testes antes de expansões.
- **Publicidade e jornalismo não compartilham acervos nem regras de aprovação.**
- Nunca adicionar segredos, tokens, credenciais ou dados de leitores ao Git.
